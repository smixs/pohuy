# Василич для OpenCode

Василич объясняет стажёру, как работает код проекта: назначение компонентов,
поток данных и причины записанных решений. Использует словарь Pohuy,
подтверждает выводы ссылками на код и завершает объяснение разделом «Короче»
из 3–4 предложений. Не изменяет проект и не заменяет ревью или проверку тестами.

## Выбор версии

| OpenCode | Готовый агент | Статус |
|---|---|---|
| V1 | [dist/v1/Василич.md](./dist/v1/Василич.md) | Формат V1; пользователь подтвердил работу Василича. Полная проверка изоляции не проводилась. |
| V2 | [dist/v2/Василич.md](./dist/v2/Василич.md) | Сделан по документации OpenCode V2; в работающем V2 не проверен. |

Текст и словарь одинаковы, настройки различаются: V1 использует `permission`
с объектом правил, V2 — `permissions` с массивом `action/resource/effect`.
Обе сборки используют `mode: all`: агент предназначен и для прямого общения,
и для вызова оркестратором. В V2 нет legacy-поля `name`: ID определяется путём файла.

Не считайте загрузку файла доказательством применения прав. В
[issue OpenCode #50598](https://github.com/anomalyco/opencode/issues/50598)
описаны проблемы Markdown permissions в V2 2.0.12 и влияние неизвестных полей,
включая `name`, в 2.0.18. Исправление в вашей версии нужно проверять отдельно.
Перед использованием V2 проверьте эффективные права и запреты записи, shell,
сети, делегирования и внешних путей на безопасном тестовом проекте.

Источники формата: [V1 Agents](https://opencode.ai/docs/agents/),
[V2 Agents](https://opencode.ai/v2/docs/agents/),
[V2 Permissions](https://opencode.ai/v2/docs/permissions/),
[V2 Tools](https://opencode.ai/v2/docs/tools/).

## Ручная установка и модель

1. Выберите готовый файл под свою основную версию OpenCode.
2. Скопируйте **один** вариант под именем `Василич.md`:
   - в `.opencode/agents/` нужного проекта — только для этого проекта;
   - в `~/.config/opencode/agents/` — глобально, для всех проектов.
3. **Уточните модель в установленном файле агента.** При необходимости добавьте
   поле `model` между первыми разделителями `---`, на одном уровне с `mode`.
   Используйте точный ID настроенной у вас модели в формате `provider/model`.
   Пример синтаксиса: `model: anthropic/claude-sonnet-4-5` — только если эта модель
   действительно доступна в вашей конфигурации. V2 также поддерживает
   `provider/model#variant`; в V1 вариант задаётся отдельным полем `variant`.
4. Полностью перезапустите OpenCode после установки или изменения файла.

Модель намеренно не зафиксирована в распространяемых сборках:

- **Вызов как сабагента (V1/V2):** поле `model` задаёт модель Василича.
  Если оно отсутствует, сабагент наследует модель родителя. Для фиксированного
  выбора укажите её явно в установленном файле.
- **Прямое общение:** проверьте активную модель в интерфейсе сессии.
  В V2 сессия хранит модель отдельно: переключение на Василича по ID не меняет
  выбранную модель сессии. Одного поля `model` в файле агента и перезапуска
  недостаточно, чтобы переключить модель существующей сессии; выберите нужную
  модель самой сессии отдельно.

Не записывайте в файл агента API-ключи.

Не устанавливайте шаблон или весь каталог `opencode/` как набор агентов:
шаблон не содержит встроенного словаря, а две версии одного агента могут
конфликтовать. Сборка и тесты для использования готового файла не нужны.
Автоматического установщика нет; npm-пакет репозитория сейчас не включает
каталог `opencode/`.

## Общение и оркестратор

Выберите Василича основным агентом в интерфейсе OpenCode либо поручите
оркестратору вызвать его. В V1 также доступно обращение `@Василич`.

Примеры вопросов:

- «Объясни, как запрос проходит от обработчика до базы».
- «Почему здесь очередь, а не прямой вызов?»
- «Разбери этот модуль так, будто я только пришёл в проект».

По умолчанию используется `ultra`. Попросите `lite`, `full` или `normal`
обычным сообщением; «хватит материться» также включает обычную речь.
Выбранный режим действует в текущем разговоре, отдельного постоянного
хранилища настроек у агента нет.

Для оркестратора есть [короткая вставка](./orchestrator.template.md).
Замените `<VASILICH_AGENT_ID>` идентификатором, под которым OpenCode
зарегистрировал агента, без `@`, расширения `.md` и угловых скобок:

- **V1:** для обычной установки Markdown-агента имя берётся из имени файла.
  Установленный `.opencode/agents/Василич.md` даёт имя `Василич`, которое
  передаётся в `task` как `subagent_type`. В нашей V1-сборке также указано
  `name: Василич`; при переименовании сохраняйте согласованность имени файла
  и этого поля и проверяйте имя в списке доступных агентов.
- **V2:** ID — путь файла относительно каталога `agents/`, без `.md`.
  Файл `agents/Василич.md` даёт `Василич`, а `agents/team/Василич.md` —
  `team/Василич`. Поле `name` для этого не требуется и в V2-сборку не включается.
  Этот ID используется при вызове инструмента `subagent`.

При рекомендованной установке под именем `Василич.md` прямо в каталог
`agents/` заменяйте `<VASILICH_AGENT_ID>` на **`Василич` в обеих версиях**.
Глобальное или проектное размещение само по себе ID не меняет. Заголовок
`# Василич` в тексте промпта не задаёт ID; каталоги исходной сборки `dist/v1/`
и `dist/v2/` в него тоже не входят, поскольку копируется отдельный файл.

Оркестратору нужно разрешение на вызов этого ID, но самому Василичу
делегирование запрещено.
В V1 инструмент называется `task`, продолжение — `task_id`; по документации V2
это `subagent` и `sessionID`. Ответ передаётся пользователю целиком с сохранением
тона, доказательств и финального резюме.

## Границы доступа

Агент использует deny-default: разрешены чтение и поиск, запрещены изменения,
запуск команд и тестов, сеть и вызов других агентов. Глобальная установка
не означает глобального доступа: работа ограничена проектом текущей сессии.
Переданный оркестратором путь сам по себе не расширяет права и не создаёт
техническую изоляцию подпапки.

Permissions и промпт — **не OS sandbox**. Поведение зависит от версии OpenCode,
эффективной конфигурации и инструментов. Маски секретов не исчерпывающие,
а запреты `read` не фильтруют результаты `grep`. Промпт требует выбирать
безопасные исходники и не искать секреты, но это не гарантия их недоступности.
Для строгой изоляции нужна отдельная среда с ограниченным доступом к файловой системе.

## Обновление и удаление

Для обновления возьмите свежую сборку нужной версии и замените установленную
копию. Сохраните собственный выбор `model`/`variant` и повторно проверьте права.
Для удаления удалите установленный `Василич.md` и уберите вставку оркестратора,
если она больше не нужна. После изменений перезапустите OpenCode.

## Сборка и проверки

Из корня репозитория:

```bash
bash opencode/build.sh
bash opencode/build.sh --check
bash opencode/build.test.sh
```

- `build.sh` собирает оба варианта из [шаблона](./vasilich.template.md),
  [skill](../skills/pohuy/SKILL.md), всех Markdown references и [LICENSE](../LICENSE).
  Служебная активация skill удаляется, лексика и сцены сохраняются.
- `--check` проверяет актуальность обеих сборок, не перезаписывая артефакты.
  Временные файлы при этом создаются внутри `opencode/` и очищаются.
- `build.test.sh` проверяет сборщик на временных копиях, включая сохранность
  корпуса, права двух форматов, устаревшие входы, ошибки источников и симлинки.
  Это не проверка реального исполнения агента OpenCode.

Сборщик не скачивает обновления, не устанавливает агента и не меняет настройки
OpenCode. Для разработки меняйте шаблон и исходники, затем пересобирайте:
ручные правки внутри `dist/` будут перезаписаны. Общие `npm test` и
`npm run typecheck` относятся к TypeScript-интеграции Pi, а не к этому сборщику.

Проверки выполнялись на Linux. На Windows нужен Git Bash или WSL; запуск
там пока не проверен. Один PowerShell/CMD без Bash недостаточен.
