# Плагин Codex

Pohuy загружает стиль в начале чата, восстанавливает его после сжатия контекста
и сохраняет выбранный режим между сессиями. Настройки доступны в карточке плагина
на клиентах с поддержкой `openai/settings`. Скиллы `setup` и `pohuy` позволяют
настроить плагин через чат.

Для запуска нужен Node.js 22.19 или новее. Команда `node` должна быть доступна
на хосте, где Codex выполняет инструменты и хуки. Установочный пакет содержит
собранный JavaScript. Python и npm на этом хосте не требуются.

## Сборка и установка

Из клона репозитория:

```bash
npm ci
npm run package:codex -- /tmp/pohuy-marketplace --compat
codex plugin marketplace add /tmp/pohuy-marketplace
codex plugin add pohuy@pohuy
```

Каталог назначения должен быть новым. Для постоянной установки выбери каталог
вне `/tmp` и сохрани его для обновлений.

После установки:

1. Включи хуки в Codex. В версии 0.162.1 за них отвечает `features.hooks` в `config.toml`.
2. Проверь команды хуков Pohuy и подтверди доверие к ним в Codex.
3. Открой новый чат и запусти настройку Pohuy.

При изменении команды хука Codex требует повторного подтверждения доверия.
Настройка через MCP работает независимо от хуков. Для автоматической загрузки
стиля нужны включённые хуки с подтверждённым доверием.

Для регистрации пакета в аккаунте собери ZIP:

```bash
npm run package:codex -- /tmp/pohuy --archive /tmp/pohuy.zip
```

Оба пути должны быть новыми. ZIP содержит один плагин без каталога marketplace.
Сборщик копирует только перечисленные в `scripts/package.mjs` файлы.
`.git`, данные пользователя и `node_modules` в пакет не входят.

В Codex 0.162.1 используй `--compat`, в том числе при сборке ZIP.
В проверке этой версии клиент обнаружил два хука compatibility-пакета
и ни одного хука переносимого пакета. Оба варианта содержат одинаковый сервер
и определения хуков. Переносимые манифесты проходят JSON Schema.

Публикация Git-ветки или изменение `websiteURL` не обновляет установленный
пакет аккаунта. Сохрани новый релиз плагина и обнови установку на нужном хосте.

Обновляй плагин через Plugins в том экземпляре Codex, где открыт чат.
Установка через CLI или отдельный daemon может оставить прежние команды
и доверие хукам в уже работающем процессе Desktop. Изменение файлов на диске
само по себе не обновляет его сессии. После обновления проверь новые записи
Pohuy в Hook stats. Ручной запуск контроллера не подтверждает автозагрузку.

## Стиль и настройки

Codex и Pi используют `extensions/pohuy/style-source.ts`. Разборщик собирает
промпт из `skills/pohuy/SKILL.md` и выбранных материалов в `references/`.
Пакет содержит исходный скилл без изменений в `codex/style/SKILL.md`.
Выбранный текст поступает агенту сразу, без поручения открывать файлы.

| Настройка | Поведение |
| --- | --- |
| Уровень | `lite`, `full`, `ultra` из исходного скилла или выключение. По умолчанию `full`. |
| Pohuy с начала чата | Загружает стиль автоматически. При выключении вызови `/pohuy full` для отдельного ответа. |
| Сколько подробностей | Кратко, по задаче или подробно. Явная просьба пользователя имеет приоритет. |
| Шутки по делу | Разрешает ситуативную иронию. |
| Словарь | Добавляет `slovar.md` и рабочий минимум из скилла. |
| Сцены | Добавляет примеры из `sceny.md`. |
| Хуенитивы | Добавляет `huenitiv.md` в режиме `ultra`. |
| Онтология | Добавляет `ontologia.md`. По умолчанию выключена. |
| Короткие тире | Заменяет длинное тире на ASCII-дефис в тексте промпта. По умолчанию выключено. |

Основные правила и примеры выбранного уровня входят в промпт независимо
от переключателей материалов. Настройки не меняют исходные файлы.
"Короткие тире" сохраняет кодовые блоки, inline-код и ссылки. Настройка меняет
также короткие напоминания хуков, но не обрабатывает готовый ответ модели.

Изменения настроек обновляют контекст на следующем ходе. При выключенном
автоматическом применении выбранный уровень и остальные параметры сохраняются.
Код и рабочие документы сохраняют профессиональные формулировки и принятый язык.

## MCP и хуки

- `settings.read({})` возвращает схему, текущие значения и разметку панели настроек.
- `settings.update({set: {...}})` сохраняет переданные поля.
- `pohuy.context({})` возвращает сохранённый режим и готовые инструкции текущему чату.
- `SessionStart` загружает стиль при запуске, возобновлении, очистке и сжатии чата.
- `UserPromptSubmit` напоминает режим или загружает полный промпт после изменения настроек.

Сервер объявляет `openai/settings` через `@openai/mcp-extensions`.
Если клиент не показывает панель, те же настройки доступны через скилл.
Скилл `setup` отвечает за первоначальный выбор режима, `pohuy` за его проверку
и изменение. Оба используют MCP и работают без контекста хука.

Локальный stdio-сервер требует хоста с Node.js. Загрузка ZIP в аккаунт
не разворачивает сервер в облаке. Для работы через удалённый MCP нужны
отдельное размещение, авторизация и хранилище пользователя.

## Данные и хост выполнения

Хук использует `PLUGIN_DATA`. Сервер использует `PLUGIN_DATA` или явно заданный
`POHUY_DATA_DIR`. В Codex 0.162.1 MCP-процесс не получает `PLUGIN_DATA`.
Для установленного пакета сервер проверяет путь
`plugins/cache/<marketplace>/pohuy/<version>` и выбирает соответствующий
`plugins/data/pohuy-<marketplace>`. При запуске вне этого каталога задай
`POHUY_DATA_DIR`. Модель не передаёт пути через инструменты настройки.

Режим хранится в `settings.json`, минимальный формат
`{"version":1,"tier":"full"}`. При отсутствии файла используется `full` без записи.
Сервер отказывается менять повреждённый файл. Обновление сохраняет неизвестные
поля и меняет только переданные настройки. Запись атомарна.

Хуки и MCP читают один файл. Настройки относятся ко всем чатам этого плагина
на текущем хосте. Между хостами они не синхронизируются.

Настройка из карточки может открыть локальный чат на Windows даже после работы
через SSH. Проверяй Node.js и MCP на хосте текущего чата.
Команда хука общая для всех платформ. Codex подставляет `${PLUGIN_ROOT}`
до запуска команды в оболочке текущей сессии. Синтаксис `%PLUGIN_ROOT%`
для `cmd.exe` не подходит для сессий с PowerShell.

## Миграция старой установки

Сначала проверь, какие файлы изменит миграция:

```bash
node codex/dist/controller.mjs migrate
```

Закрой процессы, которые могут записывать конфигурацию Codex. Затем примени
проверенные изменения:

```bash
node codex/dist/controller.mjs migrate --apply
```

Параметр `--codex-home <каталог>` выбирает старую установку явно.
Без него используются `CODEX_HOME`, `CODEX_DIR` или `~/.codex`.
Каталог данных плагина для миграции не нужен.

Миграция удаляет полные блоки между маркерами Pohuy в `AGENTS.md`
и точный старый обработчик напоминания в `hooks.json`. Остальные инструкции
и хуки сохраняются. Миграция отказывается заменять символические ссылки,
проверяет изменения файлов перед записью и создаёт резервные копии.
При ошибке записи она пытается восстановить уже заменённые файлы.
Ошибка сообщает путь к резервным копиям и ошибки восстановления, если они возникли.
Справочники остаются на месте.

Старый `install-codex.sh` тоже собирает промпт из исходного скилла через общий
разборщик. Для него нужны Node.js 22.19 или новее и Python 3.
Отдельный `AGENTS-pohuy.md` больше не используется.

Если нужна установка через глобальный `AGENTS.md`, старый способ остаётся доступен:

```bash
curl -fsSL https://raw.githubusercontent.com/smixs/pohuy/main/install-codex.sh | bash
```

Повторный запуск обновляет блок Pohuy и его хук. Для удаления старой установки:

```bash
curl -fsSL https://raw.githubusercontent.com/smixs/pohuy/main/install-codex.sh | bash -s -- --uninstall
```

## Разработка

Исходники сервера, контроллера и композиции лежат в `src/`.
`scripts/` содержит сборку, упаковку и генератор для старого установщика.
Определения хуков лежат в `hooks/`, управляющие скиллы в `skills/`.

Корневой `plugin.json` содержит идентификатор плагина и `extensions.com.openai`
с полями `interface`, `hooks` и `onboardingSkill`. Корневой `mcp.json` объявляет
stdio-сервер. `.codex-plugin/plugin.json` и `codex/mcp.json` нужны для совместимости.
При упаковке переносимого плагина управляющие скиллы попадают в корневой `skills/`.
Для установки собирай пакет. Исходный checkout содержит скилл Claude в этом каталоге.

Результат сборки в `codex/dist/` исключён из git. Пакет включает лицензии
библиотек, используемых в сборке. У `@cfworker/json-schema` лицензия отсутствует
в npm-пакете. Сборщик получает её из закреплённого коммита и проверяет SHA-256.
Этот шаг требует доступа к `raw.githubusercontent.com`.

Иконки собираются из `docs/assets/pohuy.webp`. После замены исходной картинки
запусти `npm run build:codex` или `npm run package:codex`. Сборщик создаёт
`assets/icon.png` размером 512 x 512 и SVG с тем же изображением.
Края обрезаются по центру без искажения пропорций. Обе иконки исключены
из git и включены в пакет.

```bash
npm run typecheck:codex
npm run test:codex
npm run typecheck
npm test
```

Тесты проверяют stdio MCP через SDK-клиент, схему настроек, сохранение,
содержимое промпта, хуки, упаковку и миграцию. При наличии команды `codex`
интеграционный тест устанавливает пакет в отдельный `CODEX_HOME` и проверяет
onboarding, подключение MCP и выполнение обоих хуков. Локальный HTTP-сервер
проверяет, что запрос к модели содержит стиль и сохранённый режим. Внешний
сервис модели не вызывается. Без `codex` этот тест пропускается; путь к другому
исполняемому файлу можно задать через `POHUY_TEST_CODEX`.
Отображение панели требует отдельной проверки в приложении.
